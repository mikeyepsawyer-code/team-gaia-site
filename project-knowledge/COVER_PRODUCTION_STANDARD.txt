SECTION 0 — MANDATORY BUILD RULE (NEW — ALWAYS FOLLOW)

EVERY COVER BUILD STARTS FROM THE DRIVE SOURCE PHOTO. NO EXCEPTIONS.

Rationale: Working from an already-exported JPEG and re-exporting causes
cumulative lossy compression artifacts and text-edge degradation. Each
re-export cycle compounds this loss. The only correct workflow is:

  source photo (lossless original) → one build pipeline → one export

NEVER:
 - Fetch an existing cover JPEG from GitHub and modify it
 - Patch text over an exported cover
 - Layer new text onto a previous version's output file
 - Use any file in images/ or covers/ as a source for a new build

ALWAYS:
 1. STATE the source photo filename and Drive file ID before starting
 2. FETCH the photo fresh from Drive
 3. VERIFY it is text-free (raw photo, no baked-in text)
 4. Run the full build pipeline from that raw photo
 5. Export once to the final JPEG

If you cannot locate the source photo, STOP and ask Michael.
Do not improvise from a cover archive file.

SOURCE PHOTO VERIFICATION GATE (mandatory pre-build check):
 Before writing any build code, state:
 "Source photo: [filename], Drive ID: [id], dimensions: [WxH], text-free: YES"
 If the answer is not "YES, text-free" — do not proceed.

SECTION 2 — LAYOUT ZONES

 TOP TEXT ZONE: from margin (y=112) downward
 - Title dominant word: ~2–2.5" tall, visually centered
 - Title secondary line: ~3/8" tall, same visual width
 - Gap between title lines: ~0.28" (85px)
 - Title text sits directly on photo — NO dark overlay on top

 CENTER IMAGE: pure photo, no overlays, no text
 - This is the majority of the cover
 - Uninterrupted is the goal; aim for 4–5" minimum

 BOTTOM TEXT ZONE: ~1.35" from bottom margin
 - Subtitle (italic): visually centered
 - Gap above rule = gap below rule (symmetric, ~0.18" each)
 - Rule: 55% of TEXT_W, centered, 3–4px tall, warm gold
 - Author name: visually centered
 - Bottom overlay: dark band fading up from bottom — YES, keep this

SECTION 3 — TYPOGRAPHY PREFERENCES

 TITLE — two distinct fonts expressing the contrast between words:
 - Aggressive/marker word (e.g. "Spank Me"): rough brush/marker feel,
   energetic, physical. Michael does NOT like clean geometric fonts here.
   Overheat Reckless, Fight Back, Bad Habits are the aesthetic target.
   These must be uploaded as TTF — font sites block direct download.
 - Script/calligraphic word (e.g. "Tender"): genuine calligraphic feel,
   ribbon-like, wispy, high contrast thick/thin strokes. Michael wants
   more calligraphic than Carattere but hasn't found the perfect font yet.
   Corinthia, Carattere, Imperial Script are close. Upload TTF if found.
 - Script word: red (210, 50, 50), bigger than the aggressive word
 - Aggressive word: white/cream (255, 250, 242)

 AUTHOR NAME: "Michael Sawyer" — title case (NOT all caps)
 Font: Lora Variable or similar quality serif
 Color: white/cream or metallic gold

 SUBTITLE: italic serif, natural proportions. Center visually.

 RULE: warm gold (215, 175, 130)

 AVOID SLUGS (added Aug 6, 2026): default approach for text legibility over
 art is to manipulate the TEXT's color/gradient/glow/outline so it reads
 against the painting directly — not to place a solid color plate ("slug")
 behind the text to force contrast. Slugs read as a design shortcut and
 visually interrupt the art. Use a slug only if color/gradient/outline
 treatment genuinely cannot achieve legibility after real attempts — this
 should be rare. Standing background task: when already working on a cover
 or reviewing existing cover art for any reason, check it for slugs and
 flag any found, even if that wasn't the original task.

 DEFAULT FIRST-PASS RULES (added Aug 7, 2026 — see tools/cover_build.py v9):
 NAMED "BEVELED GOLD" (Aug 7, 2026) — this is the name for the title/author/
 subtitle treatment below: chiseled emboss bevel (real distance-transform
 facets, not offset-copy fakery) + smooth airbrushed color + a second
 top-light pass giving each letter its own catch-light. Reference sheet
 (fonts x sizes x backgrounds) at project-knowledge/BEVELED_GOLD_reference_sheet.jpg.
 1. FULL WIDTH: title, subtitle, and author each scale independently to
    fill the cover width minus 1.0" total (0.25" bleed + 0.25" visual
    border, per side). At the 1950px canvas this is FULL_TEXT_W = 1650px.
    This replaces the older, more conservative width targets as the
    default starting point — "inhabit the cover," not "sit safely inside
    it." A given book can still be pulled narrower after review.
 2. TITLE + AUTHOR = gold foil by default, angled (not vertical). The
    vertical top-to-bottom gradient used through early Aug 2026 is
    RETIRED — it reads as flat horizontal banding across the letterforms.
    Use GOLD_FOIL_STOPS in cover_build.py, which are ported directly from
    assets/effects/gold-shimmer-snippet.html's animated web treatment
    (25deg, same color stops) so the static "foil still" and the animated
    "foil shimmer" read as the same gold, not two different golds.
    On WEB PAGES (not the static JPEG), if the title/author renders large
    enough on screen, use the actual animated shimmer-final CSS treatment
    from that snippet instead of a static image — the JPEG cover and an
    on-page hero title are different surfaces and can each get the
    version suited to them.
 3. SUBTITLE = sampled-palette shimmer-style gradient by default, not a
    fixed hardcoded color. cover_build.py's harmonized_subtitle_stops()
    pulls dominant colors from that book's specific source photo/painting
    via median-cut quantization, so each subtitle harmonizes with its own
    cover rather than reusing one copper/gold default across every book.

SECTION 3B — WIDTH PAIRING SYSTEM (approved Session 18)

 The approved width-pairing approach creates visual harmony between
 the top title block and the bottom text block:

 TOP BLOCK:
 Line 1 (dominant word): render at specified pt, scale to Line 1 target width
 Line 2 (secondary word): render at specified pt, scale to Line 2 target width

 BOTTOM BLOCK — MIRRORS THE TOP:
 Subtitle: scale to same pixel width as Line 2
 Author: scale to same pixel width as Line 1

 The cover reads as two mirrored typographic anchors framing the image.

 HOW TO IMPLEMENT:
 1. Render each text element at its specified pt size via ink_size()
 2. Scale to exact target width using LANCZOS
 3. Paste at visual center (find leftmost/rightmost non-transparent column)
 Never use canvas-center calculations — always find actual ink extents.

 VISUAL CENTERING — CRITICAL:
 Find leftmost and rightmost non-transparent pixel columns of the rendered
 text image. Center based on those, not on bbox or canvas midpoint.

SECTION 3C — METALLIC GRADIENT SYSTEM (approved Session 18)

 Use a 5-stop center-bright vertical gradient for metallic text.
 Light source perceived as coming from front/center of the letterform.

 GRADIENT STOPS (t = 0.0 top → 1.0 bottom):
 t=0.00–0.18  shadow → midtone (top shadow, lighter than bottom)
 t=0.18–0.42  midtone → highlight
 t=0.42–0.54  highlight plateau (brightest band, center of letterform)
 t=0.54–0.72  highlight → midtone
 t=0.72–1.00  midtone → deep shadow (bottom shadow, heavier than top)

 dark_mult = 0.48 (midtone from base)
 deep_mult = 0.35 (deep shadow from base — heavier at bottom)

 PALETTE — Radiant Sensitivity (approved):
 GOLD   base=(225,170,45)  hi=(255,248,170) → RADIANT + author
 COPPER base=(210,105,30)  hi=(255,200,90)  → Sensitivity + subtitle

 General rule: dominant title word gets gold; secondary/italic gets copper.
 Subtitle matches secondary title color. Author matches dominant title color.

SECTION 3D — GOLD TEXT FUNCTION (Kintsugi standard — approved Session ~22)

 Use actual ink pixel extents (NOT bbox) so descenders always receive gold.
 Sine curve peaks at 35% of ink height, eases to flat mid-gold by 70%,
 holds flat from 70% to 100%. NO shadow stop ever.

 gold_gradient(y_rel):  # y_rel = 0.0 top → 1.0 bottom of ink extent
   if y_rel < 0.35:
     t = sin(y_rel / 0.35 * pi/2)       # ease in
   elif y_rel < 0.70:
     t = 1.0 - (y_rel - 0.35) / 0.35   # ease out to mid-gold
   else:
     t = 0.0                             # flat mid-gold
   return lerp(mid_gold, highlight_gold, t)

SECTION 4 — PHOTO TREATMENT

 - Use original photo, ZERO brightness/contrast/saturation adjustments
   EXCEPTION: Art Amore v16 reduced brightness by 15% to make gold pop —
   see §5A for that cover's specific treatment.
 - EXIF correction: ImageOps.exif_transpose() mandatory for all Samsung Galaxy
   photos before any layout work
 - Crop to include vivid colors
 - Resize to fill full canvas (1875x2775) using LANCZOS

 CANVAS EXTENSION (when photo is too short):
 Always use the right-side background strip (x=1468+ of the 1875px canvas)
 to avoid subject bleed. Never sample from the subject area.

 BOTTOM GRADIENT:
 Cubic ease-in (t^3) starting at 65% canvas height avoids visible banding.
 color=(8,4,1), max alpha=180

SECTION 4B — FONT ACQUISITION

 Preferred method: @fontsource npm registry
 Install: npm install @fontsource/[fontname] --prefix /home/claude
 Convert: use fontTools TTFont

 CRITICAL — PARISIENNE CONVERSION:
 Convert from .woff (NOT .woff2) — the woff2 conversion produces a broken
 TTF with zero vertical metrics. PIL renders nothing from the woff2-derived TTF.
 Correct file: node_modules/@fontsource/parisienne/files/parisienne-latin-400-normal.woff
 Command: TTFont("...parisienne-latin-400-normal.woff").save("parisienne.ttf")

 CINZEL CONVERSION:
 Both .woff and .woff2 work correctly.
 File: node_modules/@fontsource/cinzel/files/cinzel-latin-400-normal.woff2

 System fonts (no install needed):
 Liberation Serif Italic: /usr/share/fonts/truetype/liberation/LiberationSerif-Italic.ttf
 Lora Variable: /usr/share/fonts/truetype/google-fonts/Lora-Variable.ttf

SECTION 8 — COMPOSITE / GHOSTED COVER ART (new, v4.0)

For covers built from a photo with additional ghosted/composited symbolic
elements layered in (as opposed to a straight photo + title treatment), per

TOOL HONESTY:
 No image-generation/diffusion AI is available in this environment. Every
 composite element (silhouettes, radiance, glow figures) is built from direct
 pixel manipulation -- PIL compositing, gradients, masks, screen-blend, not
 AI generation. State this plainly if asked to "sub out" work to a
 specialized image AI -- there isn't one available here. Do the best
 achievable version with direct compositing and say clearly where the tool's
 ceiling is (e.g., true mesh-warping to conform a shape to an architectural
 curve is NOT achievable convincingly with row-shear approximation -- say so
 rather than deliver an unconvincing fake).

ANATOMY / SOURCE ACCURACY:
 When ghosting a real photographed subject (a statue, a real object) into a
 composite more than once, do NOT create a mirrored duplicate to fill a
 second position unless the subject is genuinely symmetric. A mirrored human
 or statue silhouette is not the real subject -- it's an invented reversed
 version. Check reference photos for the subject's true, asymmetric details
 (e.g., which leg is forward, which side drapes) before duplicating. Default
 to reusing the true orientation twice over inventing a mirror.

PALETTE SOURCING:
 Don't improvise gradient/glow colors from imagination. Sample actual pixel
 values from: the source photo itself, the established gold-title gradient
 stops (see assets/effects/), and any reference mood images the person
 provides. Build the working palette from those sampled values. This produces
 a cohesive result and gives the person concrete numbers to react to and
 correct, rather than a vibe.

FILE NAMING:
 Do not use "FINAL" in cover/image work-in-progress filenames (matches the
 existing Drive naming rule, extended here to cover art generally). Use
 version numbers (v1, v2, v3...) instead. Nothing in this iterative process
 is presented as a last word.

COLORWAYS (added Aug 2, 2026 -- Chronic Bliss build session)
═══════════════════════════════════════════════════════════

COLORWAY: "Chronic Bliss Purple"
- Base: hue-varied mid-purple/lavender, anchored on RGB(152,104,212),
  organic per-pixel hue drift (~14deg) + brightness drift, not a flat swatch.
- Highlight: tight point-source beam, color RGB(238,220,255), cool-white-lavender.
  Beam computed from a virtual light source placed off-canvas upper-right,
  aimed at the cover's center, ~7deg angular width (tight). Every letter's
  highlight angle is computed from its true position relative to that single
  light point, so highlights land differently across title vs. subtitle
  blocks but stay physically consistent with one shared source.
- Approved for: title + subtitle treatment, Chronic Bliss / A Case for
  Polygasm Therapy cover.
